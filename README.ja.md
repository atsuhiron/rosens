# rosens

Room Sensoring System(部屋の環境センシングシステム).

For the English version, see [README.md](README.md).

## 概要

Rosens は、センサーから HTTP 経由で部屋の環境データ(温度・湿度・気圧)や発生回数(人感センサーの
反応回数など)を受け取り、日付ごとの [Parquet](https://parquet.apache.org/) ファイルに永続化する
FastAPI サーバーです。収集したデータをグラフ表示するダッシュボードも内蔵しています。

- **登録エンドポイント**: センサーが読み取り値を POST する。受信時刻はサーバー側(JST)で付与する
  ため、センサーは時計を持つ必要がありません。
- **取得エンドポイント**: 期間を指定して読み取り値を取得する(センサーごとにグルーピング)。
- **ダッシュボード**(`/ui`): 温度・湿度・気圧の折れ線グラフと人感センサー回数の棒グラフ。ビルド
  不要、オフラインでも動作(Apache ECharts を同梱)。

時刻はすべて JST(UTC+9)で扱います。データは `data/<種別>/YYYY-MM-DD.parquet` に、1日1ファイルで
保存されます。

## 必要要件

- Python >= 3.15
- 依存管理と実行に [uv](https://docs.astral.sh/uv/)

依存パッケージ(fastapi, polars, pydantic, uvicorn、Windows では `tzdata`)は `uv sync` で自動的に
インストールされます。

## サーバーの起動

```bash
uv sync                    # 依存関係と rosens パッケージ自体をインストール
uv run rosens-server       # 0.0.0.0:8000 でサーバーを起動
```

`rosens-server` は `0.0.0.0:8000` で待ち受けるため、LAN 内の他の端末から
`http://<ホストのIP>:8000` でアクセスできます。ダッシュボードは `http://<ホストのIP>:8000/ui` です。
一部のセンサーだけを表示するには、`http://<ホストのIP>:8000/ui?sensor_ids=home_1,home_2` のようにカンマ区切りで
指定します。

開発時に自動リロードを使う場合:

```bash
uv run uvicorn rosens.api:app --reload
```

設定は作業ディレクトリの `config.json` から読み込まれます(現状は `data_dir` のみ、既定値は
`data`)。ファイルが無い場合は既定値が使われます。

対話的な API ドキュメント(Swagger UI)は `http://<ホストのIP>:8000/docs` で確認できます。

Ubuntu 上で常時稼働のサービスとして動かす方法(systemd、journalctl)は `operation.md` を参照して
ください。

## API 仕様

時刻はすべて ISO 8601 形式です。タイムゾーン付きの値はそのまま使われ、タイムゾーンなし(naive)の
値は JST として解釈されます。

### `GET /`

ヘルスチェック。

**レスポンス** — `version` は稼働中のサーバーのバージョンです:

```json
{ "status": "ok", "version": "2.2.0" }
```

### `POST /register/environment`

環境データを1件登録する。センサーが呼び出すエンドポイント。

**リクエストボディ**

| フィールド    | 型      | 必須   | 説明                     |
| ------------- | ------- | ------ | ------------------------ |
| `sensor_id`   | string  | はい   | センサーの一意な識別子   |
| `temperature` | float   | いいえ | 温度(摂氏)             |
| `humidity`    | float   | いいえ | 湿度(%)                 |
| `pressure`    | float   | いいえ | 気圧(hPa)               |
| `uptime_s`    | integer | いいえ | センサーの稼働時間(秒) |

`sensor_id` に使える文字は英数字、`-`、`.`、`_`、`~` のみです。それ以外は 422 になります。

センサーによって測れる値が異なるため、測定値はいずれも省略可能です。センサーが提供しない値は
`null` を送るかキーごと省略してください。null として保存されます。

```json
{
  "sensor_id": "living",
  "temperature": 24.5,
  "humidity": 55.0,
  "pressure": 1008.3,
  "uptime_s": 3600
}
```

**レスポンス** — サーバーが受信時刻(JST)を記録して返します:

```json
{ "msg": "received", "received_at": "2026-07-20T13:14:37.649965+09:00" }
```

### `GET /data/environment`

期間を指定して読み取り値を取得する(センサーごとにグルーピング)。

**クエリパラメータ**

| パラメータ   | 必須   | 説明                                            |
| ------------ | ------ | ----------------------------------------------- |
| `start`      | はい   | 期間の開始(この時刻を含む)                    |
| `end`        | いいえ | 期間の終了(この時刻を含む)。省略時は現在時刻(JST) |
| `max_points` | いいえ | センサーごとの最大点数。超過分は等間隔(N点ごとに1点)で間引く。省略時は全点を返す |
| `sensor_ids` | いいえ | 取得するセンサーのカンマ区切り指定(例: `home_1,home_2`)。省略時は全センサーを返す |

**レスポンス** — センサーごとに1エントリ。各 `sequence` は古い順に並びます。センサーが提供
しなかった値は `null` になります:

```json
{
  "data": [
    {
      "sensor_id": "living",
      "sequence": [
        {
          "temperature": 24.5,
          "humidity": 55.0,
          "pressure": 1008.3,
          "uptime_s": 3600,
          "received_at": "2026-07-20T13:14:37.649965+09:00"
        }
      ]
    }
  ]
}
```

例:

```bash
curl "http://localhost:8000/data/environment?start=2026-07-20T00:00:00"
```

### `POST /register/count`

計測期間中に何かが起きた回数(例: 人感センサーの反応回数)を登録する。センサーが呼び出す
エンドポイント。

**リクエストボディ**

| フィールド   | 型      | 説明                                                         |
| ------------ | ------- | ------------------------------------------------------------ |
| `sensor_id`  | string  | センサーの一意な識別子(使える文字は上記と同じ)             |
| `count_type` | string  | 何を数えたか。現状は `"motion"` のみ受け付ける               |
| `count`      | integer | 期間中の発生回数(0 以上)                                   |
| `duration_s` | integer | 計測期間の長さ(秒、0 より大きい)。期間は受信時刻で終わる |

受け付けていない `count_type`、負の `count`、0 以下の `duration_s` は 422 になります。

```json
{
  "sensor_id": "living",
  "count_type": "motion",
  "count": 3,
  "duration_s": 300
}
```

**レスポンス** — `POST /register/environment` と同じ形式です。`received_at` が計測期間の終わりに
なります:

```json
{ "msg": "received", "received_at": "2026-07-20T13:14:37.649965+09:00" }
```

### `GET /data/count`

期間を指定して回数データを取得する(センサーと種類ごとにグルーピング)。

**クエリパラメータ**

| パラメータ    | 必須   | 説明                                                                              |
| ------------- | ------ | --------------------------------------------------------------------------------- |
| `start`       | はい   | 期間の開始(この時刻を含む)                                                      |
| `end`         | いいえ | 期間の終了(この時刻を含む)。省略時は現在時刻(JST)                             |
| `sensor_ids`  | いいえ | 取得するセンサーのカンマ区切り指定(例: `home_1,home_2`)。省略時は全センサーを返す |
| `count_types` | いいえ | 取得する種類のカンマ区切り指定(例: `motion`)。省略時は全種類を返す              |
| `bucket_s`    | いいえ | `bucket_s` 秒幅のバケットに合計する(0 より大きい)。省略時は生の値を返す         |

回数データは間引きません(`max_points` はありません)。行を落とすと発生回数が失われるためです。
長い期間を扱うときは代わりに `bucket_s` を使います。バケットは JST の 0 時を基準に区切られ
(例: `bucket_s=21600` なら 0/6/12/18 時区切り)、各データは `duration_s` の計測期間の中央を含む
バケットに入ります。バケットは生のデータと同じ形式で返り、`count` はバケット内の合計、`duration_s`
は `bucket_s`、`received_at` はバケットの終わり(集計中のバケットでは未来の時刻)になります。
データの無いバケットは含まれません。

**レスポンス** — センサーと種類の組ごとに1エントリ。各 `sequence` は古い順に並びます:

```json
{
  "data": [
    {
      "sensor_id": "living",
      "count_type": "motion",
      "sequence": [
        {
          "count": 3,
          "duration_s": 300,
          "received_at": "2026-07-20T13:14:37.649965+09:00"
        }
      ]
    }
  ]
}
```

例(1時間ごとの合計):

```bash
curl "http://localhost:8000/data/count?start=2026-07-20T00:00:00&bucket_s=3600"
```
